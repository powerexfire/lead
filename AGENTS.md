- Keep durable lead records and sales follow-up state in the authenticated shared database pipeline, while Google Sheets remains an integration source and export surface, so team follow-up survives syncs and sessions.
- App shell: authenticated layout route renders a shadcn sidebar (Leads, Settings) plus routes `/leads` and `/settings`; shared state lives in `WorkspaceProvider` (`src/components/powerex/WorkspaceContext.tsx`) consumed by both pages — keep page state there, not duplicated per page.
- GitHub Pages deployment serves the app under `https://powerexfire.in/lead/`: `.github/workflows/deploy.yml` builds with `VITE_BASE_PATH=/lead/` (default base stays `/` for Lovable hosting), copies `index.html` to `404.html` for SPA deep links, and the router uses `import.meta.env.BASE_URL` as basename — never add absolute `<a href="/...">` links or raw asset URLs; use `Link`/`to` and base-aware redirects so both hosts keep working.
- Editable integration settings (currently the Generate Leads webhook) live in the `app_settings` key/value table (key `lead_webhook_url`); the `powerex-leads` edge function reads it per request with a built-in default fallback, admins set it through the `setWebhook` action (admin enforced server-side), and users see it read-only — keep new editable settings in this table, not in code constants.
